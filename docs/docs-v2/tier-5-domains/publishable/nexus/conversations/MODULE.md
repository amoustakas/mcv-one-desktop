## 1. Purpose

`@mcv/nexus/conversations` is the central nervous system for all customer-facing messaging within the MCV.ONE platform. Every inbound message — whether it arrives via email, live chat widget, social media DM, SMS, or WhatsApp — flows through this module, is normalized into a unified conversation model, and is routed to the correct agent or bot for handling.

### The Problem

Modern businesses communicate with customers across a proliferating number of channels. Without unification, agents context-switch between separate inboxes, miss messages, lose history, and provide inconsistent experiences. Customers repeat themselves. SLAs slip. Management has no visibility.

### The Solution

This module provides:

- **Unified Inbox** — A single, filterable view across every connected channel. Email threads, live chat sessions, Instagram DMs, SMS exchanges, and WhatsApp conversations all appear in one chronological stream. Agents never need to leave the platform.

- **Real-Time Chat Engine** — WebSocket-powered live chat with typing indicators, read receipts, file sharing, emoji reactions, and message editing. Sub-200ms delivery for interactive conversations.

- **Conversation Lifecycle Management** — A well-defined state machine (`open → assigned → active → waiting → resolved → closed`) with SLA tracking at each stage, auto-close rules for stale conversations, and audit trails for every transition.

- **Intelligent Assignment & Routing** — Round-robin, skill-based, load-balanced, and manual assignment strategies. Team queues, overflow rules, business-hours awareness, and multi-tier escalation ensure the right agent handles every conversation.

- **Canned Responses** — A searchable template library with variable substitution (`{{customer.first_name}}`), shortcut triggers (`/greeting`), rich-text support, and both team-shared and personal response collections.

- **Internal Notes & Collaboration** — Private notes within conversations that are invisible to the customer. @mentions for team collaboration, internal discussion threads, and handoff context that travels with the conversation.

- **Customer Context Panel** — An integrated sidebar pulling real-time data from the CDP: customer profile, order history, previous conversations, custom attributes, lifetime value, and segment membership. Agents see the full picture without switching tabs.

- **Bot Integration & Handoff** — First-class support for chatbot interactions with structured handoff to human agents. Intent detection metadata, conversation summaries generated by the bot, and seamless escalation paths.

- **Conversation Tags & Classification** — Manual and auto-applied tags for categorization, filtering, routing, and analytics. Tag-based SLA rules and priority escalation.

- **Comprehensive Analytics** — Response time, resolution time, CSAT scores, conversation volume trends, agent performance metrics, and per-channel breakdowns. All queryable via the analytics service and streamable to external BI tools.

### Design Philosophy

1. **Channel-agnostic core** — The conversation model is the same regardless of origin. Channel-specific details (email headers, WhatsApp template IDs, social handles) are stored as metadata, not core fields.

2. **Real-time first** — Every mutation publishes to Supabase Realtime channels. The UI is always live. Polling is never required.

3. **Multi-tenant by default** — Every query is scoped by `tenant_id` via Row-Level Security. There is no code path that can accidentally leak data across tenants.

4. **Event-sourced transitions** — Conversation state changes emit events to Redpanda. Downstream consumers (analytics, SLA enforcement, notifications) react asynchronously without coupling.

5. **Composable assignment** — Routing strategies are pluggable. Teams can compose custom routing pipelines from built-in primitives or register entirely custom routers.

### 3.4 Conversation State Machine

```
                    ┌─────────────────────────┐
                    │                         │
                    ▼                         │
┌────────┐    ┌──────────┐    ┌────────┐    │
│  open  │───▶│ assigned │───▶│ active │────┘
└────────┘    └──────────┘    └───┬────┘
     │                            │
     │         ┌──────────────────┤
     │         │                  │
     │         ▼                  ▼
     │    ┌─────────┐      ┌──────────┐
     │    │ waiting │      │ resolved │
     │    └────┬────┘      └────┬─────┘
     │         │                │
     │         │                ▼
     │         │          ┌──────────┐
     └─────────┴─────────▶│  closed  │
                          └──────────┘

Transitions:
  open      → assigned   : Routing engine assigns agent
  open      → closed     : Auto-close (spam, duplicate)
  assigned  → active     : Agent sends first reply
  active    → waiting    : Awaiting customer response
  active    → resolved   : Agent marks resolved
  active    → assigned   : Reassigned to different agent
  waiting   → active     : Customer replies
  waiting   → closed     : Auto-close after timeout
  resolved  → active     : Customer reopens
  resolved  → closed     : Auto-close after grace period
```

## 4. Core Interfaces

### 4.1 Conversation

```typescript
/**
 * Core conversation entity.
 *
 * Represents a single threaded exchange between a customer and the business,
 * regardless of channel. A conversation may span multiple messages, agents,
 * and even channels (if the customer switches mid-conversation).
 */
export interface Conversation {
  /** Unique conversation identifier (UUIDv7). */
  id: string;

  /** Tenant this conversation belongs to. */
  tenantId: string;

  /** Human-readable conversation number (tenant-scoped, auto-incrementing). */
  number: number;

  /** Subject line — required for email, auto-generated for other channels. */
  subject: string | null;

  /** Current lifecycle status. */
  status: ConversationStatus;

  /** Priority level. */
  priority: ConversationPriority;

  /** Originating channel type. */
  channelType: ChannelType;

  /** Reference to the specific channel configuration used. */
  channelConfigId: string;

  /** External channel-specific conversation identifier (e.g., email thread ID). */
  externalId: string | null;

  /** Customer contact ID (references @mcv/nexus/contacts). */
  contactId: string;

  /** Currently assigned agent user ID. Null if unassigned. */
  assigneeId: string | null;

  /** Team/queue this conversation belongs to. */
  teamId: string | null;

  /** Bot that is currently handling this conversation, if any. */
  botId: string | null;

  /** Whether a bot is actively handling (vs. human agent). */
  isBotHandling: boolean;

  /** Snippet of the most recent message for list preview. */
  lastMessagePreview: string | null;

  /** Timestamp of the most recent message. */
  lastMessageAt: Date | null;

  /** ID of the agent who sent the last reply (null if customer). */
  lastAgentReplyId: string | null;

  /** Timestamp of the last agent reply. */
  lastAgentReplyAt: Date | null;

  /** Number of messages in this conversation. */
  messageCount: number;

  /** Number of unread messages (from the agent's perspective). */
  unreadCount: number;

  /** First response time in seconds (null if not yet responded). */
  firstResponseTimeSec: number | null;

  /** Total resolution time in seconds (null if not resolved). */
  resolutionTimeSec: number | null;

  /** SLA policy applied to this conversation. */
  slaPolicyId: string | null;

  /** Current SLA status. */
  slaStatus: SLAStatus | null;

  /** Applied tags. */
  tags: ConversationTag[];

  /** Custom attributes (tenant-defined key-value pairs). */
  customAttributes: Record<string, unknown>;

  /** Channel-specific metadata (email headers, WhatsApp template info, etc.). */
  channelMetadata: Record<string, unknown>;

  /** Whether this conversation is spam. */
  isSpam: boolean;

  /** Whether this conversation is starred/pinned by the current agent. */
  isStarred: boolean;

  /** ISO 8601 creation timestamp. */
  createdAt: Date;

  /** ISO 8601 last-updated timestamp. */
  updatedAt: Date;

  /** ISO 8601 resolution timestamp. */
  resolvedAt: Date | null;

  /** ISO 8601 closure timestamp. */
  closedAt: Date | null;

  /** Soft-delete timestamp. */
  deletedAt: Date | null;
}

/**
 * Conversation lifecycle states.
 */
export enum ConversationStatus {
  /** Newly created, awaiting assignment. */
  Open = 'open',

  /** Assigned to an agent but no reply yet. */
  Assigned = 'assigned',

  /** Agent is actively engaged (has replied). */
  Active = 'active',

  /** Waiting for customer response. */
  Waiting = 'waiting',

  /** Agent has resolved the issue. */
  Resolved = 'resolved',

  /** Conversation is closed (terminal state). */
  Closed = 'closed',
}

/**
 * Priority levels for conversations.
 */
export enum ConversationPriority {
  Low = 'low',
```

```typescript
  webhookPayload: Record<string, unknown>,
) {
  const channelService = new ChannelService(ctx);
  const conversationService = new ConversationService(ctx);
  const messageService = new MessageService(ctx);

  // 1. Normalize the channel-specific payload into a unified format
  const normalized = await channelService.normalizeInbound(channelType, webhookPayload);

  // 2. Find existing conversation or create a new one
  let conversation = await conversationService.findByExternalId(
    channelType,
    normalized.externalConversationId,
  );

  if (!conversation) {
    // Resolve the contact from the channel-specific identifier
    const contact = await channelService.resolveContact(
      channelType,
      normalized.senderIdentifier,
    );

    conversation = await conversationService.create({
      channelType,
      channelConfigId: normalized.channelConfigId,
      externalId: normalized.externalConversationId,
      contactId: contact.id,
      subject: normalized.subject ?? null,
      priority: ConversationPriority.Normal,
      customAttributes: {},
      channelMetadata: normalized.metadata,
    });

    // The creation event automatically triggers routing
    console.log(`Created conversation #${conversation.number} from ${channelType}`);
  }

  // 3. Add the message to the conversation
  const message = await messageService.create({
    conversationId: conversation.id,
    direction: MessageDirection.Inbound,
    senderType: SenderType.Customer,
    senderId: normalized.senderId,
    senderName: normalized.senderName,
    contentText: normalized.text,
    contentHtml: normalized.html ?? null,
    attachments: normalized.attachments ?? [],
    externalId: normalized.externalMessageId,
    channelMetadata: normalized.messageMetadata,
  });

  // 4. If conversation was resolved/closed, reopen it
  if (conversation.status === ConversationStatus.Resolved ||
      conversation.status === ConversationStatus.Closed) {
    await conversationService.reopen(conversation.id, {
      reason: 'Customer sent a new message',
    });
  }

  return { conversation, message };
}
```

```typescript
import { MessageDirection, SenderType, ConversationStatus } from '@mcv/nexus/conversations';

/**

 */
async function sendAgentReplyWithCanned(
  ctx: TRPCContext,
  conversationId: string,
  cannedResponseId: string,
  overrides?: { additionalText?: string },
) {
  const cannedResponseService = new CannedResponseService(ctx);
  const messageService = new MessageService(ctx);
  const conversationService = new ConversationService(ctx);

  // 1. Fetch the canned response template
  const template = await cannedResponseService.getById(cannedResponseId);

  // 2. Fetch context for variable resolution
  const conversation = await conversationService.getById(conversationId);
  const variableContext = await cannedResponseService.buildVariableContext({

    contactId: conversation.contactId,
    agentId: ctx.userId,

  });

  //    e.g., "Hi {{customer.first_name}}" → "Hi Sarah"

    template.contentText,
    variableContext,
  );

  const resolvedHtml = template.contentHtml
    ? cannedResponseService.resolveVariables(template.contentHtml, variableContext)
    : null;

  // 4. Append any additional text
  const finalText = overrides?.additionalText
    ? `${resolvedContent}\n\n${overrides.additionalText}`
    : resolvedContent;

  // 5. Create the outbound message
  const message = await messageService.create({
    conversationId,
    direction: MessageDirection.Outbound,
    senderType: SenderType.Agent,
    senderId: ctx.userId,
    senderName: ctx.userDisplayName,
    contentText: finalText,
    contentHtml: resolvedHtml,
    attachments: template.attachments.map((a) => ({
      fileName: a.fileName,
      fileSize: a.fileSize,
      mimeType: a.mimeType,
      storageKey: a.storageKey,
      url: a.url,
    })),
    isAutomated: false,
  });

  // 6. Update canned response usage stats
  await cannedResponseService.recordUsage(cannedResponseId);

  // 7. Transition conversation to 'waiting' (awaiting customer reply)
  if (conversation.status === ConversationStatus.Active ||
      conversation.status === ConversationStatus.Assigned) {
    await conversationService.updateStatus(conversationId, ConversationStatus.Waiting);
  }

  return message;
```

```typescript
  const typingTimeoutRef = useRef<ReturnType<typeof setTimeout>>();

      startTyping();
    }

    // Reset the stop-typing timeout
    if (typingTimeoutRef.current) {
      clearTimeout(typingTimeoutRef.current);
    }
    typingTimeoutRef.current = setTimeout(() => {
      stopTyping();
    }, 3000);

  const handleSend = useCallback(async () => {
    if (!draft.trim()) return;

    await sendMessage({
      direction: MessageDirection.Outbound,
      senderType: SenderType.Agent,
      contentText: draft.trim(),
    });

    setDraft('');
    stopTyping();
  }, [draft, sendMessage, stopTyping]);

  if (isLoading) return <LoadingSkeleton />;

  return (
    <div className="flex flex-col h-full">
      {/* Conversation header */}
      <ConversationHeader
        conversation={conversation}
        assigneeOnline={conversation.assigneeId
          ? onlineAgents.has(conversation.assigneeId)
          : false}
      />

      {/* Message list with infinite scroll */}
      <MessageList
        messages={messages}
        hasMore={hasMore}
        onLoadMore={loadMore}
      />

      {/* Typing indicator */}
      {typingUsers.length > 0 && (
        <TypingBubble users={typingUsers} />
      )}

      {/* Reply input */}
      <ReplyComposer
        value={draft}
        onChange={handleInputChange}
        onSend={handleSend}
        conversationId={conversationId}
      />
    </div>
  );
```

### Example 5: Bot Integration with Handoff

```typescript
import {
  ConversationBotService,
  ConversationService,
  AssignmentService,
} from '@mcv/nexus/conversations';
import { BotHandoffReason, ConversationStatus } from '@mcv/nexus/conversations';

/**
 * Process a customer message through a bot, with automatic
 * escalation to a human agent when the bot cannot handle it.
 */
async function processBotMessage(
  ctx: TRPCContext,
  conversationId: string,
  customerMessage: string,
) {
  const botService = new ConversationBotService(ctx);
  const conversationService = new ConversationService(ctx);
  const assignmentService = new AssignmentService(ctx);

  const conversation = await conversationService.getById(conversationId);

  // Skip if not currently handled by a bot
  if (!conversation.isBotHandling || !conversation.botId) {
    return null;
  }

  // 1. Get the active bot session
  const botSession = await botService.getActiveSession(conversationId);

  // 2. Process the message through the bot provider
  const botResponse = await botService.processMessage(botSession.botId, {
    conversationId,
    message: customerMessage,
    sessionContext: botSession.context,
    messageHistory: botSession.messageHistory,
  });

  // 3. Check if the bot wants to escalate
  if (botResponse.shouldEscalate) {
    // Generate a conversation summary
    const summary = await botService.generateSummary(conversationId);

    // Create the handoff record
    const handoff = await botService.createHandoff({
      conversationId,
      botId: conversation.botId,
      reason: botResponse.escalationReason ?? BotHandoffReason.BotUncertain,
      reasonMessage: botResponse.escalationMessage,
      botSummary: summary,
      detectedIntent: botResponse.detectedIntent,
      sentimentScore: botResponse.sentimentScore,
      collectedInfo: botResponse.collectedInfo ?? {},
      botMessageCount: botSession.messageCount,
    });

    // Transfer to human routing
    await conversationService.update(conversationId, {
      isBotHandling: false,
      botId: null,
    });

    // Route to the appropriate team
    await assignmentService.routeConversation(conversationId, {
      source: 'bot_handoff',
      handoffId: handoff.id,
      preferredTeamId: botResponse.targetTeamId,
      context: {
        summary,
        intent: botResponse.detectedIntent,
        sentiment: botResponse.sentimentScore,
        collectedInfo: botResponse.collectedInfo,
      },
    });

    // Send a system message about the handoff
    await botService.sendHandoffMessage(conversationId, {
      customerMessage: 'Let me connect you with a team member who can help further.',
      internalMessage: `Bot handoff: ${botResponse.escalationReason}. Summary: ${summary}`,
    });

    return { action: 'handoff', handoff };
  }

  // 4. Bot can handle — send the response
  await botService.sendBotMessage(conversationId, {
    text: botResponse.text,
    contentBlocks: botResponse.contentBlocks,
    quickReplies: botResponse.quickReplies,
  });

  // 5. Update session context
  await botService.updateSession(conversationId, {
    context: botResponse.updatedContext,
    messageCount: botSession.messageCount + 1,
  });

  return { action: 'responded', response: botResponse };
}
```

```typescript
    warningThreshold: 0.75, // 75% of target elapsed
  });

    const status = await slaService.evaluateStatus(item.conversationId);

    // Check for new warnings
    for (const metric of ['firstResponse', 'nextResponse', 'resolution'] as const) {
      const metricStatus = status[metric];

          actualSec: metricStatus.elapsedSec,
        });

      }
    }
  }
```

## 7. Error Codes

All errors in this module follow the MCV error format: `NEXUS_CONV_<CODE>`.

| Code | HTTP | Error Key | Description | Resolution |
|------|------|-----------|-------------|------------|
| 1001 | 404 | `NEXUS_CONV_NOT_FOUND` | Conversation not found or not accessible in this tenant. | Verify the conversation ID and tenant context. |
| 1002 | 409 | `NEXUS_CONV_INVALID_TRANSITION` | Invalid status transition (e.g., `closed → assigned`). | Check the state machine diagram. Only valid transitions are permitted. |
| 1003 | 422 | `NEXUS_CONV_ALREADY_ASSIGNED` | Conversation is already assigned to another agent. | Use `reassign` instead of `assign`, or wait for the current agent to release. |
| 1004 | 403 | `NEXUS_CONV_ACCESS_DENIED` | Agent does not have permission to access this conversation. | Ensure the agent is assigned, on the team, or has supervisor/admin role. |
| 1005 | 429 | `NEXUS_CONV_RATE_LIMIT` | Too many conversation operations in a short period. | Implement exponential backoff. Rate limit: 100 ops/min per agent. |
| 1006 | 422 | `NEXUS_CONV_MERGE_CONFLICT` | Cannot merge conversations across different contacts. | Both conversations must belong to the same contact, or merge contacts first. |
| 1007 | 422 | `NEXUS_CONV_MERGE_SELF` | Cannot merge a conversation with itself. | Provide two distinct conversation IDs. |
| 2001 | 404 | `NEXUS_MSG_NOT_FOUND` | Message not found. | Verify the message ID. |
| 2002 | 422 | `NEXUS_MSG_EMPTY` | Message has no content (no text, no HTML, no attachments). | Provide at least one content field. |
| 2003 | 413 | `NEXUS_MSG_ATTACHMENT_TOO_LARGE` | Attachment exceeds the channel's maximum file size. | Check `channel.capabilities.maxAttachmentSize` for the limit. |
| 2004 | 422 | `NEXUS_MSG_ATTACHMENT_TYPE_NOT_ALLOWED` | Attachment MIME type is not allowed for this channel. | Check `channel.capabilities.allowedAttachmentTypes`. |
| 2005 | 422 | `NEXUS_MSG_TOO_LONG` | Message exceeds the channel's maximum length. | Check `channel.capabilities.maxMessageLength`. Truncate or split. |
| 2006 | 502 | `NEXUS_MSG_DELIVERY_FAILED` | Failed to deliver message to the external channel. | Check channel health status. The message is saved locally; retry delivery. |
| 2007 | 422 | `NEXUS_MSG_EDIT_NOT_SUPPORTED` | This channel does not support message editing. | Check `channel.capabilities.messageEditing`. |
| 3001 | 404 | `NEXUS_CHANNEL_NOT_FOUND` | Channel configuration not found. | Verify the channel config ID. |
| 3002 | 422 | `NEXUS_CHANNEL_INACTIVE` | Channel is not active. Messages cannot be sent. | Activate the channel in admin settings. |

## 8. Security

### 8.1 Multi-Tenant Isolation

Every database table in this module is protected by PostgreSQL Row-Level Security (RLS) policies. The `tenant_id` column is the primary isolation boundary.

```sql
-- Applied to ALL nexus_* tables
ALTER TABLE nexus_conversations ENABLE ROW LEVEL SECURITY;

CREATE POLICY tenant_isolation ON nexus_conversations
  USING (tenant_id = current_setting('app.current_tenant_id')::uuid);
```

**Guarantees:**

- No query can return data from another tenant, even with SQL injection.
- `tenant_id` is set from the authenticated JWT, not from user input.
- All Drizzle queries automatically include the tenant filter via middleware.
- Cross-tenant operations are impossible at the database level.

### 8.3 Data Protection

**Channel Credentials:**

- All channel credentials (API keys, tokens, passwords) are encrypted at rest using AES-256-GCM.
- Credentials are decrypted only in memory during channel operations.
- Credential fields are never returned in API responses (masked as `***`).
- Webhook secrets are stored hashed (bcrypt) for signature verification.

**Message Content:**

- Message content is stored in plain text (for search functionality).
- Sensitive data detection runs on inbound messages and can auto-redact:
  - Credit card numbers → `****-****-****-1234`
  - Social Security Numbers → `***-**-1234`
  - Custom patterns defined per tenant.
- File attachments are stored in tenant-isolated Supabase Storage buckets.
- Attachments are served via signed URLs with configurable expiration (default: 1 hour).

**PII Handling:**

- Customer PII (name, email, phone) is referenced via `contactId`, not duplicated in conversation records.
- Denormalized sender names in messages are kept for audit trails but can be anonymized via the data retention system.
- GDPR delete requests trigger cascading soft-deletion of all conversation data for the contact.

### 8.4 Webhook Security

All inbound webhooks are verified before processing:

```typescript
// Webhook verification middleware
async function verifyWebhook(req: Request, channelConfig: ChannelConfig): Promise<boolean> {
  const signature = req.headers['x-webhook-signature'];
  const timestamp = req.headers['x-webhook-timestamp'];
  const body = await req.text();

  // 1. Verify timestamp is within tolerance (5 minutes)
  const requestTime = parseInt(timestamp as string, 10);
  const now = Math.floor(Date.now() / 1000);
  if (Math.abs(now - requestTime) > 300) {
    throw new ConversationError('NEXUS_CHANNEL_WEBHOOK_INVALID', 'Webhook timestamp expired');
  }

  // 2. Compute expected signature
  const expected = computeHMAC(
    `${timestamp}.${body}`,
    channelConfig.webhookSecret,
  );

  // 3. Constant-time comparison
  if (!timingSafeEqual(signature as string, expected)) {
    throw new ConversationError('NEXUS_CHANNEL_WEBHOOK_INVALID', 'Invalid webhook signature');
  }

  return true;
}
```

### 8.6 Audit Trail

Every significant action is recorded in the `conversation_events` table:

- Status changes (with before/after values)
- Assignment changes
