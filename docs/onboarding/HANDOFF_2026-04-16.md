## A. Schema honesty — add `metadata` to the Contact zod schema

**Where**: `src/lib/schemas/crm.ts` (Contact zod schema)
**Symptom**: Two `as unknown as { metadata?: ... }` casts in the codebase right now:
- `src/views/CRMView.tsx` — `FromOnboardingLink` reads `contact.metadata.completion_journey_id`
- `src/views/CapitalFoundationView.tsx` — `PinnedInvestorBanner` reads `contact.metadata.completion_journey_id`

**Why**: The `contacts` table has a `metadata` jsonb column populated by
`runJourneyCompletionEffects` with `prospect_id`, `completion_journey_id`,
`track`, `country`, `role_hint`. The TS Contact schema doesn't surface it,
so consumers cast through. Clean fix: add `metadata: z.record(z.unknown()).optional()`
to the Contact schema, then drop the casts.

**Watch out for**: existing CRM mutations may not pass metadata through. If
`useUpdateContact` strips unknown fields, that's fine — completion-effects
writes via service-role insert directly, not through the user-facing mutation.
Verify nothing else breaks by spot-checking the contact-create + contact-update
paths.

**Estimated**: ~10 min.

**Why**: Tony often wants to see "all leads/contacts that came through onboarding"

**Specific deliverables**:

**Watch out for**: filter state should persist via the navigation store or URL
query so a refresh keeps the user in the same view.

## C. Agent avatar → AgentProfileView in wizard chat

**Where**: `apps/onboarding/src/components/AgentChatColumn.tsx`

**Why**: The wizard chat shows agent avatars on every assistant message + in the
header. Clicking should jump to the Desktop's `AgentProfileView` (shipped in PR #34)
so the prospect — or an admin watching over their shoulder — can see the full
specialist context (persona bio, tool belt, recent conversations).

**Catch**: AgentProfileView lives in the Desktop app at port 5173, not in
apps/onboarding (port 3201). Cross-domain navigation, not a `setView` call.
Two options:

1. **Open in new tab** to `${DESKTOP_ORIGIN}/?view=agent-profile&handle=@amara`
   (need to add a `?view=` query param consumer in the Desktop app's
   navigation store — small lift).
2. **Modal-in-place** — fetch agent_persona row by handle in the wizard
   and render a slim profile inline. Heavier lift but no cross-domain dep.

**Recommendation**: Option 1. The Desktop and onboarding apps deploy independently
but live under the same root domain in prod. Cross-domain link with
`target="_blank"` is the cleanest UX (admin spectator opens it in a new tab,
prospect doesn't even see the Desktop app).

**Estimated**: ~15-20 min for option 1.
